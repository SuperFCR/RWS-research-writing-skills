# 章节执行与审查

## 整篇起草或实质重写

主代理先锁定用户要求的活动章节路径与角色。每个主要章节分派独立的新子代理；不要求同时运行，受并发限制时分批执行。摘要、共享术语、bibliography 和主文件由主代理整合。一次改句或单章修订不因此扩大成整篇协作。

每章的 `.writing/tasks/<section>.md` 至少包含：

- 本轮目标、唯一可写 TeX 路径和负责人。
- 章节角色、段落论证链及范围约束；如有 `.writing/narrative.md`，提供本章相关的核心价值与必须报告的事实。
- 用户材料中的相关摘录、证据表、段落蓝图、方法/实验约束。
- 已有标签、引用键、术语和相邻章节接口。
- 验收条件：关键内容、证据边界、模板要求；篇幅仅按用户/投稿要求给定。
- 交付：实际改动文件、使用证据、未解决问题、自审结果。

子代理只写分配的章节文件及指定本地交付记录；不得修改 main、共享宏、bib 或别章，不得安装软件、操作 Git 或推送，不得递归派发整篇任务。需要新增文献/共享宏时提出建议，由主代理核验并合入。给子代理最少的相关上下文，不把整套历史对话反复复制。

`.writing/chapter-agents.md` 记录章节、agent 标识、任务包、输入、产物、自审和主代理接受状态。主代理保持用户沟通、处理共享文件及交叉章节问题，所有章节完成后检查整体论证一致性。不能只根据代理一句「完成」接受交付。

如果当前环境没有子代理能力，准确告知限制，并就整篇任务是否改用逐章单代理执行取得用户决定；在等待时仍可整理材料和证据。若用户已明确允许单代理，记录后继续，不重复询问。不要虚构子代理记录。

## 两阶段审查（每章适用）

在 `.writing/reviews/<section>.md` 记录以下结果及必要修订：

1. 规范：是否完成任务包/用户范围；文件是否实际被 main 引用；模板、宏、标签与引用键是否有效；需要时本地编译，并核对 missing/undefined citation、reference 和正文布局。
2. 内容：新增论断对应哪些证据；方法、数据和统计口径是否一致；结论是否越界；段落是否形成论证；过程指令或草稿注释是否混入可见正文。

内容审查同时使用 [反防御性表达规则](anti-defensive.md)：贡献明确、表达直接，并核对改写没有改变数据、证据、关键限制或掩盖不利结果。

整篇任务由主代理审查子代理交付。单章直接编辑可以自审，准确记录审查者，不冒称独立评审。检查不通过则返修；缺真实数据、全文或必要决策时记录具体阻碍和下一步，不用占位字数或编译成功替代内容完成。

完成后更新 `.writing/progress.md`，简要记录产物、来源、验证证据与下一步。只有同步已获授权时，再按工具层执行发布检查。
