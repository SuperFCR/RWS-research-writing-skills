# 写作层

正文的唯一工作版本是论文项目中的 `.tex`。先读已有要求、当前主文件的 `\input`/`\include` 及有关章节，保留模板、命令、标签、引用键和用户选定的结构。现有上下文足够时直接推进，不要求固定轮数的访谈或逐章重复确认。

## 1. 项目档案与恢复

首次开始实质写作时，用 `overleaf-ctl list` 找到项目，必要时按工具层登记已有 Git 项目，再执行：

```bash
overleaf-ctl writing init ALIAS
```

命令仅创建缺少的 `.writing/project.md`、`outline.md`、`progress.md` 和 `layout.json`，保留已有文件。把已知要求和本轮范围填入记录；未知内容标为待补，只在影响当前决策时询问。不要把原样初始化的提示文字当作完成的项目档案。

恢复工作先读这四个文件，再核对当前主文件和 Git diff。`layout.json` 是初始化时的清单，不是永远正确的章节路由；章节变动后更新它及大纲。实际被主文件引用的文件优先，勿误写 backup、before_change 或未启用的备用章节。

- `project.md`：研究问题、目标期刊/会议、语言、篇幅和模板要求、已有材料、结论边界。
- `outline.md`：实际 TeX 路径、章节角色、要支持的论点、所需证据和验收条件。
- `progress.md`：已改内容、重要决定、使用的资料、验证结果、遗留问题与下一步。
- 证据、任务包、审查和资料摘录按需写入 `.writing/` 下的文件，不预建空文件夹。

只有用户要求初始化新论文且没有现有 TeX/模板时使用 `--scaffold`。默认编号结构与已有项目适配规则见 [references/project-layout.md](references/project-layout.md)。不要自动拆分或替换已有主文件。

局部改句只需读取相关上下文、简短更新进度并检查改动；无需整篇任务包、无关文献搜索或多代理。

## 2. 先整理证据，再写正文

引言、相关工作和新增文献性论断，先按 [references/evidence.md](references/evidence.md) 整理 `.writing/evidence-map.md` 和当前章节的段落蓝图，再写进对应 `.tex`。已有证据表足够时复用并只补变化。

优先消费用户资料和已核验文献。引用必须支持所写的具体论断；检索元数据或 DOI 存在不能证明文章支持某项结论。全文不可用时限制在已读摘要或摘录范围；不能补造实验细节或文献。缺依据的论断留在本地档案作为问题，不写成已证实事实。

方法、实验与结果使用用户提供的数据和实验日志。把来源、统计口径、图表映射及允许的结论记录在 `.writing/`；任何布局演示数据只留本地并明确标注，不混入可提交的实验结果。

## 3. 贡献主线与反防御性表达

有了证据和段落蓝图后，按 [references/anti-defensive.md](references/anti-defensive.md) 确定证据支持的核心价值，减少防御前缀、无依据的自我贬低与实验流水账。整篇任务或主线重组时按需维护 `.writing/narrative.md`；局部改句只做相关检查。

明确表达研究的贡献，保留影响结论的不利结果、必要限定和合理不确定性；不为突出优势改换预设指标、隐藏基线或编造取舍理由。此规则同时进入章节任务包和内容审查。

## 4. 分章执行与审查

整篇起草或实质重写：按 [references/chapter-workflow.md](references/chapter-workflow.md) 给每个主要章节创建任务包，分派独立子代理，各自独占一个章节文件；主代理负责结构、共享文件和最终审查。子代理不可再次分派整篇，也不可操作 Git 推送。

单章任务可直接执行，但都要经过两类检查：

- 规范检查：完成本轮要求、改对活动章节、符合模板、标签/引用/依赖完整，必要时编译。
- 内容检查：论断有支撑、论证连贯、术语与其他章节一致、实验条件与结论边界准确，没有过程提示混入正文；反防御改写没有夸大贡献或遗漏关键结果。

任何检查失败先修复或准确记录阻碍，不靠字数、引用数量或禁词命中率声称学术质量达标。保持自然、具体的论文表达，不为去 AI 化删除事实或限定条件。

## 5. 完成与同步

更新进度，说明改了哪些 TeX 文件、用了哪些证据、做了哪些检查和仍缺什么。需要 PDF 时调用工具层编译并检查引用/交叉引用警告及布局；编译成功仅表示构建成功。

写作过程产物全部留在 `.writing/`，构建产物在 `.outputs/`。实际用于论文的图片、表格和 bibliography 留在项目原有路径。不要创建另一份 Markdown 章节稿、独立 LaTeX 输出树或默认上传审查报告。

用户要求发布时加载 [../tools/SKILL.md](../tools/SKILL.md)，审查改动后使用受保护的同步命令。初始化与写作不自动推送。
